# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

「지구 서버: 문명의 시대」 — a trade game web app for a Korean 6th-grade social studies unit (「3. 국가 간의 경제 활동」, lessons 13–17). 25 students in 6 groups, each group runs one country on a hex map; trade, dependence, a crisis, and a treaty emerge from play. It is season 2 of an earlier "지구 서버 신발 시장" game and reuses some of its structure (student roster/device connection, "연결 초기화" recovery).

User-facing text, docs, and commit messages are in Korean.

## Current state of the repo

There is **no application code, package.json, build, lint, or test setup yet**. The repo holds:

- `docs/design.md` — the full design spec (lesson timeline, rules, data model, server functions, priorities P0–P4, recovery playbook, art list). Read the relevant section before implementing anything.
- `docs/trade_setup.sql` — Supabase install script (schema `priv` + `public.game`, ~120 functions, `images` storage bucket for student flag/emblem uploads). Its header says it is **generated by `node tools/trade/build-sql.mjs`** with rule numbers from `app/trade/js/rules.js`; do not hand-edit it once that generator exists — change the source and regenerate. It is written to be re-runnable without wiping in-progress game data. Apply it by pasting the whole file into the new Supabase project's SQL Editor and running it (re-runs only refresh rule numbers and functions).
- `app/trade/assets/` — game-ready sprites (see below).

Paths referenced by the docs but not present yet: `app/trade/js/rules.js`, `tools/trade/build-sql.mjs`, and the simulation code `earth-trade/sim/sim.mjs`, `earth-trade/data/rules.mjs`, `earth-trade/data/map.mjs` (all rule numbers in the design were tuned by that 6-country simulation, design §10). Ask the user before assuming where these live.

## Architecture (planned, per docs/design.md §11)

- Static web app on **Netlify** + a **new, separate Supabase project** (not the shoe game's). Three screens: student, teacher control room (관제실), and electronic whiteboard.
- All game logic lives in Postgres functions. Student functions (`my_state`, `map_view` with fog filtering, `worker_build`, `offer_create`, `offer_respond`, …) each **lock per country before checking**; teacher functions are `admin_*` (`admin_next_turn` does production/consumption/happiness/unrest/factories/logging in one call).
- Tests run against a local in-process **PGlite** database; never rehearse against production.
- Must-test invariants (design §11): 25 concurrent users without lost writes within a country; turn advance never produces twice; world-discovery notice fires once; one offer accepted concurrently by two users settles once; unprocessed offers expire on phase change; backup download and forced phase move work.
- After classes start, **do not change the data structure**, and preserve saved student records across sessions.

## Assets

- `app/trade/assets/cities/` — 6 capitals + 3 neutral city-states; `app/trade/assets/buildings/` — 11 buildings. All 160×160 RGBA PNG. Each folder has a `manifest.json` (ids, Korean labels, paths relative to that folder). Anchor is `[0.5, 0.83]`: align the image's bottom-center point to the hex tile center.
- These are prototype art; the game must still run with placeholder shapes when art is missing, and art is swapped in as it arrives (design §12). Replacing art must not change game rules or saved student data.
- **Source/high-res art lives in the separate `nation` repo** (`C:\projects\nation`, github.com/ys970425/nation) in `buildings/ units/ sheets/ events/ archive/`. Only copy into this repo what the game actually loads, sliced/resized to target size; do not add raw sheets or an `art-src/` folder here. Modern military units are intentionally kept only in `nation/archive/`.
- File names: lowercase English, underscores, no spaces or Korean.
- Art style and target sizes are listed in design §15 (2D isometric-style pixel art, transparent PNG; terrain hex 128×148 pointy-top, resources/units/icons 64×64, improvements 128×128, cities 160×160). Do not imitate any real game's art or UI.

## Design guardrail

The causal story must hold (design §0): countries lack things or others make them cheaper → they trade → dependence and competition → an unannounced trade restriction causes real damage → countries agree on a reasoned treaty. Fun comes first; avoid mechanics that turn it into "war, collapse, magical treaty revival."

## 작업 규칙
- 이 앱은 초등 6학년 사회 수업용이다. 화면 문구는 6학년이 이해할 수 있는 쉬운 한국어로 쓴다.
- 답변은 한국어 존댓말로, 결론부터 짧게 쓴다. 전문 용어는 쉽게 풀어서 설명한다.
- 파일을 새로 만들거나 고치기 전에 계획을 먼저 보여 주고, 내가 승인한 뒤에 실행한다.
- 기준 문서는 docs/design.md다. 설계가 바뀌면 design.md도 같이 고친다.
- 이미지 원본 보관소는 C:\projects\nation이다. 내가 요청하기 전에는 nation을 수정하지 않는다.
- 게임 이미지는 app/trade/assets/ 아래에만 두고, 파일명은 영어 소문자와 하이픈·밑줄만 쓴다.
- 파일 버전을 이름으로 나누지 않는다(최종, v2 같은 복사본 금지). 버전 관리는 git 커밋으로만 한다.
- 커밋 메시지는 한국어로 짧게 쓴다. 푸시는 내가 직접 한다.
- 모든 화면 하단에 제작자 표기를 넣는다: "myoLab(산쌤)"
- 기능을 하나 끝낼 때마다 내가 브라우저에서 확인하는 방법을 알려 준다.
- 작업 보고의 맨 끝에는 항상 "지금 푸시하세요(Sync Changes)" 또는 "아직 푸시하지 마세요"를 이유와 함께 한 줄로 알려 준다.

## 작업 분담
- 너(Claude)는 계획, 검토, 최종 확인을 맡는다. 코드를 직접 길게 쓰지 않는다.
- 분량이 많거나 단순한 코딩은 터미널에서 codex exec로 GPT에게 맡긴다.
  파일 수정이 필요한 작업이면 codex exec --help로 쓰기 허용 옵션을 확인해서 쓴다.
  codex exec에는 항상 `-c 'windows.sandbox="unelevated"'`를 붙인다. (없으면 Windows에서 모든 명령이 막힘)
- 맡길 때는 작업 범위, 고칠 파일, 완료 조건을 분명히 적고,
  결과는 "바뀐 파일과 내용 5줄 요약"으로만 보고받는다.
- 결과는 git diff로 확인하고, 문제가 있으면 다시 맡긴다.
- 헬피코드는 직접 호출할 수 없다. (2026-12-31까지 헬피코드 우선)
  - 결정이 끝난 내용을 문서에 옮기거나 정리하는 일도 헬피코드에게 맡긴다. Claude는 결정, 작업지시서, 검토만 한다.
  - GPT 크레딧이 없을 때는 GPT 몫도 헬피코드에게 아주 구체적인 지시서로 맡기고, 실패하면 Claude가 그 부분만 직접 고친다.
  - 헬피코드에 맡길 작업은 docs/tasks/next.md에 작업지시서로 쓰고 나에게 알려 준다.
  - 알려 줄 때는 항상 "헬피코드에게 ~를 명령하세요" 형식으로, 내가 그대로 전달할 수 있게 쓴다. 이 줄은 보고의 맨 끝, 푸시 안내 바로 위에 둔다.
  - 작업지시서에는 작업 범위, 고칠 파일, 완료 조건, 하지 말아야 할 것을 분명히 적는다.
  - 내가 "헬피코드 끝"이라고 하면 docs/tasks/report.md와 git diff를 확인해서 검토하고, 문제가 없으면 커밋한다.
  - 헬피코드는 커밋과 푸시를 하지 않는다. 커밋은 Claude가 검토 후에 한다. 작업지시서에도 매번 이 내용을 적는다.
- 새 프로젝트를 만들거나 추가 결제가 필요한 일은 반드시 나에게 먼저 묻는다.
