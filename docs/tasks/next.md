# 헬피코드 밤샘 지시서 (2026-11-17 밤) — E10 첩보 + E11 성찰 양식

## 헬피 명령 규칙 (반드시 지킴)
1. 시험은 `npm run ...` 한 줄 명령만. `$env:Path` 수정·`cmd /c`·파이프/리디렉션·`node -e` 금지.
2. 시험은 관련 수정을 모두 끝낸 뒤 한 번에 돌린다. 중간에 돌리지 않는다.
3. npm을 못 찾으면 재시도하지 말고 `docs/tasks/report.md`에 적고 코드 작성을 계속한다.
4. git 명령(commit, push, add 등) 금지. `2>&1`, `|` 파이프 금지.

## 먼저 알아 둘 것 (오늘 바뀐 것)
- **돈·자원 흐름은 하나예요**: 국고(`war.countries.coin` + `war.inventory`) ↔ 역할 지갑(`war.wallets`, 역할별). 요청 승인·분배는 국고 → 역할 지갑, 회수·반납은 그 반대. `war.role_wallets` 표는 이제 안 써요(건드리지 않음).
- 생산·화면의 「내 재고」는 `war.wallets`(역할)를 읽어요. 이 흐름은 `tests/war/budget.test.mjs`·`trial.test.mjs`가 지켜요. 이 시험이 깨지면 내 수정이 잘못된 거예요.
- 가짜 미리보기(`npm run war:preview`)는 `tools/war/make-preview.mjs`가 만들어요. 실제 데이터 미리보기(`make-real-preview.mjs`, `private/`)는 열지도 고치지도 않아요.
- 화면 「첩보 정보」 메뉴는 지금 자리표시 글만 있어요 (`app/war/js/war-app.js`의 `첩보 정보` 패널). 이걸 진짜로 채워요.

## E10. 첩보: 정찰병이 적 도시 옆에 있으면 그 나라 정보를 본다

### 규칙 (무역 게임의 칸 방식처럼 「칸 거리」로 정해요)
- 정찰병(`scout`)이 **다른 나라 도시가 있는 칸과 바로 이웃한 칸(거리 1)**에 있으면 그 나라를 「본다」. 거리 2 이상이면 못 본다. 도시 칸 위에 서는 것은 이번엔 다루지 않는다(그 경우 보지 않음).
- **동맹 나라는 대상이 아니다** (적·중립만). 우리 나라 도시도 아니다.
- 본 순간의 **스냅샷**을 저장한다: 그 나라의 ① 국고(코인·창고 자원) ② 각 역할 지갑 ③ 공장·고등 건물이 있는 도시 목록(도시 id·이름·시설 종류, 폐허 여부). 「○턴에 본 정보」로 남고, 정찰병이 떠나도 지워지지 않으며, 다시 옆에 가면 새 스냅샷으로 **바뀐다**(같은 나라는 한 줄만).
- 언제 보나: (a) 정찰병이 움직여 도착한 직후 (b) 다음 턴이 시작될 때(가만히 서 있어도 갱신). 정찰병이 여러 명이면 각자 본 나라를 모두 반영.
- **우리 나라 모든 역할**이 같은 첩보를 본다(공병사령관이 보면 육군 참모총장 화면에도). 다른 나라는 절대 볼 수 없다(누수 금지).
- 정찰병을 잡거나 잡히지 않는다(기존 규칙 유지): 공격 불가·피격 불가.

### 서버
- 새 표 `war.intel(observer int, target int, seen_turn int, data jsonb, primary key(observer, target))` — `schema.sql`에 더한다(재실행 안전하게 `if not exists`, 권한은 기존 표와 같은 방식으로 막는다).
- 이웃 칸 계산은 기존 `war.neighbors(...)`(war_produce가 쓰는 방식) 재사용. 새 내부 함수 `war.intel_refresh(country)`를 만들어 위 (a)(b)에서 부른다. `war_move`와 다음 턴 처리 함수 끝에 한 줄씩 부르는 것만 허용(그 밖의 동작은 바꾸지 않는다).
- `war_poll`의 `country` 덩어리에 `intel`(우리 나라가 본 것만)을 더하고, 바뀌면 `war.bump('country', observer)`.
- 가져오기(`war_admin_import` 초기화)가 `war.intel`도 비우게 한다.

### 화면 (1366×768)
- 「첩보 정보」 메뉴(모든 역할): 나라별 카드. 나라 이름·색 + 「○턴에 본 정보」 + 국고 코인·창고 자원 칩 + 역할별 지갑 + 공장·고등 건물 도시 목록. 비어 있으면 「정찰병을 적 도시 바로 옆 칸에 보내면 볼 수 있어요」.
- 카드의 도시 이름을 누르면 지도에서 그 도시로 이동(기존 `centerOn` 방식).
- 글자 잘림·가로 스크롤 없게.

### 시험: `tests/war/intel.test.mjs` (새 파일, `npm run test:war:intel`)
- 거리 1에서 보임 / 거리 2에서 안 보임 / 도시 칸 위에서는 안 봄.
- 동맹 나라는 안 보임, 우리 나라는 안 보임.
- 스냅샷 내용이 그때의 국고·지갑·공장과 같음. 이후 상대 재고가 바뀌어도 첩보는 그대로, 다시 옆에 가면 새로 바뀜(`seen_turn` 갱신).
- 정찰병이 떠나도 정보가 남음. 다음 턴에 가만히 서 있으면 갱신됨.
- 같은 나라의 **다른 역할 학생**이 `war_poll`로 같은 첩보를 받음. **다른 나라 학생은 받지 못함**(누수 시험, 필수).
- 정찰병이 없으면 첩보가 비어 있음. 가져오기(초기화) 뒤 비워짐.
- 가짜 미리보기(`make-preview.mjs`)에 예시 첩보 1건(1번 나라가 2번 나라를 본 상태)을 넣어, 처음 온 사람이 「첩보 정보」 메뉴에 내용이 있는 것을 보게 한다. 넣은 뒤 `trial.test.mjs`가 그대로 통과해야 한다.

## E11. 성찰 양식: 게임이 끝난 뒤 학생이 돌아보는 양식

(설계 12장의 「의견 보내기」와는 **다른 기능**이에요. 의견 보내기는 이번에 만들지 않는다.)

### 질문 (글은 `app/war/js/war-reflect.js`의 `QUESTIONS` 한 곳에만 둔다 — 선생님이 나중에 고치기 쉽게)
큰 버튼으로 고르기 3문항 (한 문항에 버튼 3~4개, 한 번에 하나만 고름, 버튼은 크고 손가락으로 누르기 좋게):
1. 「우리 나라는 자원을 어떻게 나눴나요?」 — 모두 똑같이 / 급한 역할 먼저 / 이유를 잘 말한 사람 먼저 / 잘 모르겠어요
2. 「내 요청이 거절되거나 줄었을 때 어땠나요?」 — 이해했어요 / 조금 속상했어요 / 이유를 더 듣고 싶었어요 / 그런 일이 없었어요
3. 「다시 한다면 무엇을 바꾸고 싶나요?」 — 미리 의논하기 / 더 아껴 쓰기 / 외교·무역 더 하기 / 바꿀 게 없어요
짧은 글 1문항 (200자까지, 글자 수 표시): **「자원을 나눌 때 가장 고민한 것은?」**
- 안내(빨간 글씨): 「친구 이름은 쓰지 마세요」
- 전부 답해야 「보내기」가 눌린다. 보낸 뒤 「고마워요!」 화면. 한 학생은 **한 번만**(다시 열면 이미 보냈다고 알려 줌, 수정 불가).

### 언제 열리나
- 교사가 관제실에서 「성찰 열기 / 닫기」 버튼으로 연다(기본은 닫힘). 열려 있을 때만 학생 위쪽 메뉴에 「돌아보기」 버튼이 보이고, 닫혀 있으면 제출이 `REFLECT_CLOSED`로 막힌다.

### 서버
- 새 표 `war.reflections(student int primary key, country int, role text, a1 int, a2 int, a3 int, free_text text, created_at timestamptz default now())` — **이름은 저장하지 않는다**(학생 id만).
- `war.game`에 `reflect_open boolean not null default false` 더하기(`add column if not exists`).
- 학생: `war_reflect_submit(p_a1 int, p_a2 int, p_a3 int, p_text text)` — 역할 있는 학생만, 열려 있을 때만, 한 번만(`ALREADY_DONE`), 선택 번호 범위 검사(`BAD_ANSWER`), 글 200자 초과·빈 글 거절. `war_reflect_state()` — 열렸는지·내가 이미 냈는지.
- 교사: `war_admin_reflect_set(p_open boolean)`, `war_admin_reflect_list()` — 모든 응답(나라·역할·번호 답·글·시각)과 **문항별 선택 수 집계**. 학생 이름·학생 id는 돌려주지 않는다.
- 교사 전용 함수는 기존 `war_admin_*`와 같은 방식(교사 uid 확인)을 쓴다.

### 화면
- 학생: 「돌아보기」 버튼 → 한 화면에 질문 4개(큰 버튼 + 글 칸). 1366×768에서 스크롤 없이 또는 한 번 스크롤로 끝까지 보이게.
- 교사 관제실(`war-admin.js`): 「성찰 모아 보기」 구역 — 열기/닫기 버튼, 제출 수 / 전체 수, 문항별 막대(버튼별 몇 명), 응답 목록(나라·역할·짧은 글), 「AI에게 넘기기」 → 마크다운 글을 **복사** 또는 **.md로 내려받기**.

### AI에 보내는 글에서의 개인정보 (중요)
- 내보내는 마크다운에는 **학생 이름·번호·학생 id·기기 id를 넣지 않는다.** 나라 번호·역할·고른 답·글·시각만.
- 글 속에 이름이 섞였을 수 있으니, 내보낼 때 **명단(`priv.students`의 이름)에 있는 이름은 「○○」로 바꾼다**(서버 함수 `war_admin_reflect_export()` 안에서 처리해 교사 화면은 그 결과만 쓴다). 바꾼 개수를 맨 위에 적는다.
- 이 데이터는 질문 봇(`tools/war/qna-proxy.mjs`, `app/war/js/war-qna.js`)과 **섞이지 않는다**: 봇이 성찰 표를 읽거나 보내지 않음을 확인한다.

### 시험: `tests/war/reflect.test.mjs` (새 파일, `npm run test:war:reflect`)
- 닫힘 → `REFLECT_CLOSED`, 열기 → 제출 성공, 두 번째 제출 `ALREADY_DONE`.
- 선택 번호 범위 밖 `BAD_ANSWER`, 빈 글·201자 글 거절, 역할 없는 학생 거절.
- 교사 목록·집계 숫자가 맞음. **목록에 학생 이름·id가 없음**(필수).
- 내보내기 글에 이름이 안 남음(글 속에 학생 이름을 일부러 넣어 「○○」로 바뀌는지), 번호·id도 없음.
- 학생 uid로 교사 함수 호출 거절. 열기/닫기 반복 동작.
